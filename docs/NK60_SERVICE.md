# NK60 V2 用户态服务

`servers/keyboard/service.c` 将现有微内核机制、实际板级驱动、便携键盘引擎和 USB HID 状态机连接起来。它使用静态内存，不依赖 VFS、旧 RTOS、HAL 或动态分配器；固件入口是 `nos_keyboard_service()`。`nk60_service_init/step()` 保留注入 I/O 的边界，供真实驱动与自动化模型使用。

## 运行与错误

- TIM2 是 1 MHz、32 位微秒计数器。服务按增量累积毫秒，正确跨越约 71 分钟的硬件回绕；不直接将计数器除以 1000 作为系统时间。
- 矩阵扫描目标间隔为 4 ms。72 个移位槽的时序延迟和系统调用都有开销，因此不宣称实板 1 kHz；`scan_overruns` 记录超期与扫描自身耗时超标，必须上板测量实际延迟。
- 每轮扫描前后轮询 USB；只有 USB 核心接收整个快照后才弹出键盘 FIFO。端点背压期间保留按下与释放；引擎溢出时释放并等待全部松开。
- USB 配置、挂起、恢复状态变化会清空按键，并等待物理全部松开后接收新按键。远程唤醒要求主机授权、挂起至少 5 ms，每次物理按下只申请一次；USB 状态机将唤醒脉冲限制为 2 ms。
- 控制器错误会断开 USB、关闭灯光并记录 `usb_errors`，需要复位；Flash 不可用时键盘继续工作，配置明确为易失。状态还包含扫描、保存、RGB、报告溢出和 UART 丢弃计数。
- 外置 NOR 忙等待、擦除校验和长读取有进度回调。保存期间只继续扫描、USB 与报告传输，不重入 Flash，不执行 UART 配置命令或 RGB 传输。

## UART 配置

PA9/PA10、115200 8N1，命令和数字采用 ASCII、十进制。输入行最多 95 字符，超长行整行丢弃并在下一行恢复，支持 CR/LF/CRLF 与退格。输入每轮最多处理 16 字节。输出进入 1024 字节环形缓冲，每轮最多发送两个字节；UART 未就绪保留待发数据，缓冲溢出通过 `uart_dropped` 明确统计，不同步阻塞整条状态行。

读取 `help`、`status` 无须解锁。修改配置前同时按住 **Esc + PN + Fn 两秒**，获得 30 秒 UART 修改窗口；`lock` 立即锁定。已消费的长按不能在手动锁定或窗口过期后自动重新解锁，必须先松开。这里是接触板上 UART 的物理维护接口，不是 VIA/Vial；独立 USB NLP 改键通过 peer 绑定权限控制。

| 命令 | 行为 |
| --- | --- |
| `help` / `status` | 使用说明、当前配置和错误计数 |
| `lock` | 锁定配置写入 |
| `defaults` | 恢复默认布局，释放当前所有按键 |
| `bind L K T P C` | 设置层 L、物理键 K 的动作类型 T、参数 P 和 usage C |
| `macro M [usage ...]` | 设置宏 0–3，最多 8 个 usage；不带 usage 清空 |
| `nkro 0` / `nkro 1` | 切换报告协议下的 6KRO/NKRO；Boot 协议始终 8 字节 |
| `debounce MS` | 设置对称逐键消抖，合法范围 1–50 ms |
| `rgb MODE BRIGHTNESS` | 模式0关闭、1静态RGB、2层色、3呼吸、4彩虹、5波浪、6响应、7逐键；亮度0–255 |
| `save` | 将保存提前排队，仍等待全部松开和引擎 FIFO 排空 |

`bind` 的层范围为 0–3，物理键范围为 0–60；行列和默认 Fn/PN 布局见 [键盘功能](KEYBOARD_FEATURES.md)。类型由 `config.h` 明确定义：0 禁用、1 透明、2 普通 usage、3 修饰位图、4 瞬时层、5 切换层、6 修饰/轻触、7 层/轻触、8 一次性修饰、9 Consumer usage、10 宏、11 本地控制。所有参数经过同一配置校验，再原子应用；修改后先释放按键并等待全部松开。

例如将 A 键（物理位置 29）改为 B：

```text
bind 0 29 2 0 5
```

设置一个依次输出 A、B 的宏，并绑定到同一位置：

```text
macro 0 4 5
bind 0 29 10 0 0
save
```

修饰位图使用 HID 顺序（bit0 左 Ctrl、bit1 左 Shift 等）；层或宏编号使用参数 P，普通键及 Consumer usage 使用 C。宏采用逐步按下/释放，不执行脚本、不启动进程。

## 保存与电流边界

JEDEC 探测确认容量后，服务保留外置 Flash **最后两个 4 KiB 扇区**作为 NOS 键盘配置日志，紧前两个扇区供 NLP 持久启动计数。首次初始化只读；空白、旧版本或损坏记录使用默认配置。首次修改后等待 60 秒无新修改，再等待物理全松开、宏结束和引擎报告 FIFO 排空。`save` 仅缩短等待，不绕过这些条件。

写入另一扇区，完整校验后最后写提交标记；失败保留上一提交记录，保留脏状态并延迟重试。保存前复制稳定配置快照，进度扫描期间发生的新本地修改不会被误标为已保存。旧固件若使用整个外置 Flash，须先备份尾部数据；没有旧存储格式迁移或自动整片擦除。

灯光在 USB 配置完成前、取消配置或挂起时断电；挂起状态变化时立即关闭，不等待 100 ms 灯光刷新周期。每个 RGB 通道最高实际 PWM 为 16/255，因此 61 灯全白的通道和至多 2928，低于按每通道 20 mA 估算的 300 mA 软件预算（通道和 3825）。这是保守的软件限幅，仍须测量灯珠、稳压器与整板实际电流。

**当前 CPU 仍以 84 MHz 轮询。关闭 RGB 不等于全板满足 USB 挂起电流要求；STOP/时钟恢复、全板低功耗和电气合规尚需后续实现与实板验证。** 灯光可显示层状态及主机 Caps Lock LED；这里没有独立 LCD/OLED。

## 自动化边界

运行 `python3 tests/host_nk60_service.py`：链接实际服务、键盘引擎、NOR 日志和 HID 核心，注入物理驱动与主机传输模型。检查按下/释放、USB 背压、物理解锁与过期、UART 边界与非阻塞输出、宏配置和执行、Flash 擦除期间继续输入、失败保留旧配置、挂起断灯、PWM 预算、远程唤醒和微秒回绕；启用 ASan、UBSan 与泄漏检测。

模型验证服务行为，不证明实际 HC595 电气、USB 枚举、晶振、SPI/DMA 波形、Flash 型号或 USB 电流合规。固件构建和板级验收见 [NK60 V2](NK60_V2.md)，USB 与硬件各自有独立测试和待验收范围。

## NLP

实际服务在 `link.c/link_caps.c` 初始化并合作式轮询 NLP。USB vendor 接收经严格分帧后进入用户态 endpoint，注册 device/keyboard/log/keymap/lighting/keyboard_control。物理解锁将30秒配置权限绑定当时 UID/boot，对端改变、reset 或到期撤权。完整1056字节配置上传经过 SHA256、generation 与现有配置语义校验，原子提交后使用旧安全保存流程，响应区分易失和待保存。RGB tuple与61键颜色由新v2记录扩展共同持久化。模型新增实际字节流发现/读写/权限/断线回归；不声明实板验证。详见 [NLP](protocols/nlp/implementation.md)。

## 逐键RGB与偏好扩展

`lighting.c/layout.c`提供61键真实宽度、独立RGB、7种点亮模式及关闭，10fps上限、Caps Lock/Caps Word指示、按键响应、待机熄灯与估算电流限制。`color R G B`、`led key R G B`、`effect speed idle_seconds LED_mA`沿用物理解锁。`rgb mode brightness`现在接受mode0..7。`defaults`同时重置键位与灯光，并显式解除未知偏好schema的保存锁定。

灯光参数与逐键配色作为224字节扩展和1056字节键位共同双槽提交，旧记录加载默认灯光；新代码旧save接口保留扩展。未知扩展禁止覆盖保存。RGB tuple不再只存在RAM。产品只读NLP能力和逐键帧事务、命令例子、扩展插槽见 [能力与扩展](NK60_CAPABILITIES.md)。
