# 阶段 0–5 执行计划

<!-- Copyright (C) 2026 NOS contributors -->

本计划执行 [开发计划](DEVELOPMENT_PLAN.md) 中的修复与架构工作。实现、来宾验证、外部硬件验证分别记录；代码落盘不等于阶段验收完成。最终软件结果见 [验证报告](VALIDATION_RESULTS.md)；外部条件保持单独列出。

## 分工与集成规则

| 工作线 | 负责范围 | 主要交付 |
|---|---|---|
| 内核 agent | 通用内核、ABI、任务、对象与调度 | 锁与回收修复，多端点 IPC、服务重启、线程/futex、权限、IRQ 对象、SMP 调度 |
| 内存与架构 agent | 内存、异常入口、页表、MPU、跨核机制 | 映射事务和范围操作、W^X/guard、共享地址空间、三架构 SMP、TLB 同步 |
| C 库 agent | 用户运行库、Newlib、musl、线程接口 | 安全 I/O、重入/TLS、真实 pthread、锁/条件变量、C 库兼容范围 |
| VFS 与设备 agent | 用户态 VFS、驱动、持久化后端 | 文件生命周期、目录、dup/pipe、virtio-blk、原生双 bank 文件系统、FatFs、设备中断 |
| ELF 与应用 agent | ELF 加载、init、独立应用、RV32 | 安全装载与参数/TLS、正常 shell、STM32 PIE、RV32 Sv32/非 MMU 平台 |
| 构建与测试 agent | 构建依赖、环境、CI、验证工具 | 配置签名、完整矩阵、资源循环、启动/存储/SMP/MPU/RV32 验收与独立报告 |
| 主 agent | 集成审查、旧应用迁移、总体执行 | 内核编译器辅助函数权限边界、Lua/LVGL 用户态应用、跨模块问题跟踪、最终验证和文档 |

共享头由指定负责人维护；每条工作线使用独立输出目录做开发验证。最终验收在全部相关改动落盘后重新执行，保留代码、构建配置、镜像与工具版本身份。

## 阶段验收清单

### 0：稳定性

- [x] F01–F12 有实现或明确的故障处理契约，并有对应回归证据。
- [x] 原有 8 个组合与新增错误路径全部通过。
- [x] 每个原有平台运行 1,000 轮资源创建/退出/回收，并恢复资源基线。
- [x] 配置改变触发重编译、静态库改变触发重链接、无变化保持增量构建。
- [x] 验证报告可区分完整与局部矩阵，保留失败和通过的独立运行记录。

### 1：微内核对象与服务

- [x] 内核按任务、调度、IPC、同步/对象拆分，syscall 编号与 ABI 版本固定。
- [x] 多端点通信、授权/撤销、超时/取消、陈旧回复拒绝和服务退出回收通过。
- [x] 多锁及传递优先级继承、循环等待检测和孤儿任务回收通过。
- [x] VFS 故障后客户端收到错误，init 能重启服务，旧资源不误用新实例。
- [x] 正常启动与自测模式独立，正常 init 在应用退出后继续运行。

### 2：内存与加载器

- [x] 地址空间独立引用计数支持线程共享和创建者先退出。
- [x] 范围保护/释放、PROT_NONE、失败回滚、页权限、栈 guard 通过。
- [x] 内核代码 RX、数据 RW/NX；编译器生成的内存调用和 libgcc 辅助函数归特权代码。
- [x] ARM、ARM64、RV64 静态 ELF 与 STM32 PIE 独立构建、装载、执行、退出通过。
- [x] 无效 ELF、参数/段越界及加载失败资源回收通过。
- [x] argc/argv/envp/auxv、BSS、C 库及真实 ELF TLS 通过。
- [x] STM32 的可选 MPU 配置有真实 QEMU 权限故障验证；无 MPU 配置保留共享内存契约。

### 3：C 库与 POSIX 子集

- [x] 标准 FD、安全缓冲区、长写入、零长度、短读写与 errno 契约通过。
- [x] Newlib 与 musl 的真实 malloc/stdio/线程/TLS 测试通过。
- [x] pthread create/join、mutex、condition、线程私有数据与退出清理通过。
- [x] Newlib 共享地址空间的跨核重入与分配器/stdio 同步通过。
- [x] 支持范围表逐项说明；不支持的 Linux/POSIX 操作不返回伪成功。

### 4：设备与应用迁移

- [x] 用户态 UART 与正常 shell 可运行，交互能力按 QEMU 模型实际结果记录。
- [x] 用户态 virtio-blk 的 MMIO、DMA、权限和真实 IRQ 通知通过。
- [x] 原生文件系统与 FatFs 在三种 MMU 平台跨启动写入/重新挂载/读回通过。
- [x] 持久化损坏校验、代际回退和未知磁盘拒绝覆盖通过。
- [x] 旧 Lua 与 LVGL 库作为真实独立用户应用执行；软件渲染与硬件显示验证分开。
- [x] USB/输入/显示的板级服务迁移与测试条件记录，不以软件模拟冒称物理外设通过。
- [x] 真实 STM32 runner 与板级配置准备完成；有硬件后执行并保存结果。

### 5：SMP 与架构扩展

- [x] ARM、ARM64、RV64 的次级 CPU 真实启动并并发执行不同用户线程。
- [x] per-CPU 上下文、调度互斥、跨核唤醒/取消、共享内存锁竞争通过。
- [x] 其他 CPU 缓存旧页表时的权限撤销/释放与 TLB 同步通过。
- [x] RV32 Sv32 与非 MMU 目标分别实际运行，指针/ABI/异常宽度差异有回归。
- [x] 单核 STM32 及既有 8 组合保持通过。
- [x] 按原计划，动态链接、完整信号/fork、网络和交换属于按应用需求安排的后续兼容目标，不因为完成上述基线就宣称支持。

## 外部执行条件

- [ ] 真实 STM32 板：环境没有 `/dev/ttyACM*` 或 `/dev/ttyUSB*`；runner 与配置已准备，尚未执行物理板验证。
- [ ] 远端 CI：现有 `git ls-remote origin HEAD` 成功；读取 `https://api.github.com/repos/wkcs/nos/actions/workflows` 返回 `Forbidden`。不能由此推断全部 Git 凭据失效。已在云环境草稿添加 `api.github.com`，待设置应用后重试；当前没有远端 CI 成功记录。
- [ ] USB、物理显示与输入驱动：旧 RTOS 实现仍在 legacy，尚未迁移成新设备服务。原计划按实际应用需求推进，本轮交付的迁移是 FatFs、Lua、LVGL 软件渲染；不将其写作板级外设通过。
- [ ] 完整 Linux/POSIX 兼容、glibc、动态链接、完整信号/fork、网络与交换：仍是后续兼容目标，不在当前已验证支持表内。

阶段 0–5 的可执行软件条目与上述外部/条件交付分别验收。真实板与远端 CI 尚未满足原计划的全部外部验收条件，因此不能把本报告描述为“所有硬件和 CI 工作均完成”。

执行结果由 `tests/acceptance.py` 按工作线归档；阶段状态以实际结果与最终实现报告更新，不能只依据 `NOS TEST PASS` 字串忽略缺失检查项。
