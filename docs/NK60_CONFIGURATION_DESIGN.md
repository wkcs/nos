# NK60 配置系统实现指南

当前实现统一使用 `KEYBOARD (0x0100 / 0x20)`，固件、C++ CLI、Web、Rust SDK/CLI 必须配套更新。
最新逐字节协议见 [wire contract](NLK_KEYBOARD_CONFIG_WIRE.md)，本轮修正范围见
[实施记录](superpowers/plans/2026-11-17-keyboard-corrections.md)。

## 配置与运行态

- 基础配置：按键映射、带参数的 action 绑定、触发/轴体相关配置；由唯一编译配列定义扩展。
- 灯光配置：零到 `CONFIG_KEYBOARD_LIGHT_MAX_LAYERS` 个平等图层，每层独立效果、参数、矩形、z、透明度和触发方式。没有主灯效或 `off` 灯效。
- 宏配置：名称、说明及按序执行的按下/释放/点击/延时步骤。
- 唯一聚合配置 `/data/keyboard/config.nkc`：选中的基础/灯光引用、全局灯光开关、目录版本与提交序号。

用户对象是文件系统中的真实对象：`base/<id>/<revision>.nkc`、`light/<id>/<revision>.nkc`、
`macro/<id>/<revision>.nkc`；目录为 `_catalog/<revision>.nki`。没有 `~` 虚拟档案。编译灯效库用于
创建图层，不伪装成已保存的配置文件。对象与目录先写入并同步，最后原子替换聚合配置；根记录是唯一发布点。
CRC 错误、无法核对的提交、损坏的非空 LittleFS 不会触发自动格式化或静默回默认值。

## 编辑与保存

有效修改通过 PATCH 立即发送设备并应用到 RAM；宏编辑只安装播放数据，不自动发按键。未完成的分批文档
暂留草稿，保留上一份有效运行态并返回状态标志，界面显示校验提示。分配失败保持原草稿、版本与运行态。
灯光编辑期间的全局开关使用租约内操作7，也只改 RAM；物理 action 的灯光开关仍按运行态策略合并落盘。

只有主动选择覆盖/另存才发布文档和聚合引用。放弃、租约超时或连接失效会释放草稿并加载已保存的运行态。
离开页面、切配置或关闭应用时提示未保存修改。租约60秒，客户端每15秒续期。

实体 action 通过类型化 runtime request 入队；按键扫描路径不执行文件系统操作。基础/灯光下一份、上一份
在已保存配置中切换。选择与物理开关采用5秒空闲、30秒最长、5秒最小间隔合并落盘；宏播放不改聚合配置。

## 扩展入口

- 配列：`definitions/layouts/<id>.c`，Kconfig 选择唯一编译配列。
- Action：`definitions/actions/<id>.c`，必需 `execute`、可选参数 schema 和跨字段校验；不存在内置/外置分组。
- 灯效：`definitions/effects/<id>.c`，提供参数描述和渲染回调，每个图层有独立实例状态。
- CMake 扫描源码并生成显式描述符指针数组，链接器保留引用；不依赖手写注册清单或运行时文件扫描加载代码。
- Web 特殊字段控件按 action/配列/效果注册；灯光可视化由 effect renderer 与坐标映射注册表扩展。

生产键盘引擎与头文件中已删除通过 `NLK_HOST_TEST` 保留的旧协议/manifest/配置存储实现。主机测试编译真实
生产引擎，另分别覆盖真实 VFS/LittleFS 对象事务、实际服务/引擎联测、HID/action/宏和图层合成。
`NLK_HOST_TEST` 只在其他通用模块需要平台替身时使用；键盘测试还分别带/不带该宏编译，验证行为一致。

## 页面与灯光展示

五个页签：按键配置、灯光配置、宏配置、按键测试、配置档案。轴体设置归入按键配置。复用原键盘外壳、键帽和
页面设计语言；没有“在设备上预览”按钮。灯光修改自动应用设备 RAM，同时网页按图层进行动画合成。
网页触发模拟清楚标注为仅影响页面，不伪装成键盘真实触发状态；未知扩展效果可注册自己的网页 renderer。
按键测试使用页面能实际观察到的浏览器输入，不声称得到未实现的设备逐帧 NKRO 遥测。

## 服务边界与资源预算

NLK 核心注册能力并转发报文，在服务循环中调用能力可选的 `on_poll`。键盘能力注册完成后，RPC 和持久化由同一个
执行上下文串行处理。按键扫描只提交动作，在存储访问期间可继续运行。板级配置提供持久化设备名和 NLK 栈预算。

键盘配置的协议适配层负责请求解析、会话校验和编码。文档层负责配列定义、配置文档编码与校验，配置服务负责
临时编辑、实时应用和提交顺序。对象存储负责版本记录和聚合配置的原子发布。

键盘服务向远程 VFS 注册配置文件和子树的写保护范围。远程读取和导出仍可用，修改受管理的配置经由键盘能力
提交。策略只作用于远程 VFS 能力，本机 VFS 仍提供管理访问。旧 `/data/keyboard/active.nkc` 可以正常删除。

编译定义从只读表直接编码到响应页，页边界可以截断任一字段。文件分页读取在一次完整记录校验后返回指定切片。
启动时目录索引解码到未发布的存储状态。更新当前选择时使用独立的聚合记录缓冲区，只有目录内容变动才编码目录
索引。草稿按实际内容分配，基础运行态只缓存执行所需的 action 绑定和参数。

键盘扫描栈和 NLK 栈分别由 `CONFIG_KEYBOARD_STACK_SIZE` 和 `CONFIG_NLK_SERVER_STACK_SIZE` 配置。
NK60 V1、V2 的 NLK 栈预算为 6144 字节，由固件构建的持久化路径和 RPC 路径测量校验。V1 的 240 KiB
应用区采用板级应用编译选项。启用符号回溯时保留帧指针。硬件验证见[验证记录](NK60_CONFIGURATION_VERIFICATION.md)。
